# 字段与接口来源文档

- 更新日期：2026-11-06
- 适用对象：微信云开发数据库 `anime` / `airing_schedule` / `sync_state` / `match_review`，以及小程序端字段映射 `miniapp/src/cloud/normalize.js`
- 相关文档：[IMPLEMENTATION](./IMPLEMENTATION.md#1-数据模型) · [ADR-0005](./adr/0005-cloud-database-integration.md)

> 说明：`animeSync` 云函数已实现三个外部接口的调用与落库逻辑；集合中现有 21 条数据仍是 `miniapp/src/data/anime.js` 种子数据，需手动触发同步后才会写入接口数据。下表「接口来源」为实现数据同步时的字段映射。

## 1. 数据来源总览

| 编号 | 来源 | 用途 | 接入方式 | 当前状态 |
| --- | --- | --- | --- | --- |
| S1 | AniList | 季度番剧主目录、封面、简介、放送状态、下一集时间 | GraphQL：`https://graphql.anilist.co`，`Page.media` / `Page.airingSchedules` | 已实现（`animeSync` → `season` / `schedules`） |
| S2 | Bangumi（bgm.tv） | 中文名、中文简介、Bangumi 评分、跨站匹配 | REST v0：`POST /v0/search/subjects`、`GET /v0/subjects/{id}`；默认镜像 `https://api.bgmapi.com` | 已实现（`animeSync` → `bangumi`） |
| S3 | AnimeSchedule | 每周分集放送时间表、延期标记 | REST v3：`timetables` 接口 | 代码已接入，待配置 Token 与链路验证 |
| S4 | 种子数据 | 当前 21 部番剧的完整可用数据 | `miniapp/src/data/anime.js` 一次性写入 | 已落库 |
| S5 | 自建（云开发） | 跨站 ID 匹配结果、时区换算、同步状态、人工审核 | 云函数与云数据库 | 部分落库 |

推荐数据流：

```text
AniList 季度列表（S1）
  → 以 anilist_id 为主键写入 anime
  → Bangumi 搜索/详情（S2）补充 title_cn、synopsis、bgm_id
  → AnimeSchedule 周表（S3）写入 airing_schedule
  → 自建匹配与同步状态（S5）记录 sync_state / match_review
  → 小程序云函数 animeApi 读取 anime / airing_schedule
```

### 6.2 Bangumi v0（S2）

- 默认请求镜像 `https://api.bgmapi.com`：无代理环境直连官方 `api.bgm.tv` 会长时间无法建立连接（本机实测 20 秒未建连），云函数环境同样没有代理；可用环境变量 `BANGUMI_BASE_URL` 切回官方域名。

## 7. 时间与枚举规则

- **时间存储**：所有 `airing_at` / `next_airing_at` 统一存 UTC；展示字段（`airing_date`、`airing_time`、`airing_day`）按 `Asia/Shanghai` 生成。
- **星期换算**：`0 = 周一 … 6 = 周日`，禁止直接使用 JS `getDay()`（0 为周日）。
- **ISO 周**：`week_key` 使用 `YYYY-Www`，按 ISO-8601 计算，用于 AnimeSchedule 周表与 `sync_state` 对账。
- **状态枚举**：`anime.status` 为 `airing / finished / upcoming`；`airing_schedule.status` 为 `scheduled / aired / delayed`。
- **空值策略**：云开发控制台 JSON 模式不接受 `null`、空字符串、空数组，写入前会剔除；因此「当前是否落库」列中标记为「否」的字段需通过云函数写入。

## 11. 同步云函数 `animeSync` 使用说明

源码：`miniapp/cloudfunctions/animeSync/`，构建后同步到小程序产物的 `cloudfunctions/animeSync/`。

### 11.1 action 一览

| action | 作用 | 主要参数 | 写入集合 |
| --- | --- | --- | --- |
| `season` | 拉取 AniList 季度列表 | `season`、`seasonYear`、`page`、`perPage`、`hideSeed` | `anime`、`sync_state` |
| `schedules` | 拉取时间区间内的分集放送时间 | `from`、`to`（秒级时间戳）、`page`、`perPage` | `airing_schedule`、`sync_state` |
| `bangumi` | 为缺少 `bgm_id` 的番剧匹配 Bangumi 中文名 | `limit`（默认 2，最大 6）、`retryReview`（是否重跑审核项，最多重试一次） | `anime`、`match_review`、`sync_state` |
| `animeschedule` | 按 ISO 年/周拉取 AnimeSchedule 时间表 | `year`、`week` | `airing_schedule`、`anime`、`sync_state` |
| `all` | 依次执行 `season`（第 1 页）+ `schedules` | 同 `season` / `schedules` | 同上 |

### 11.2 调用示例（云端测试事件）

### 11.3 运行约束

- 首次执行 `season` 默认把 `seed_*` 番剧置为 `is_visible: false`，避免种子数据与接口数据重复展示；传 `"hideSeed": false` 可保留。
- AniList 每页最多 50 条，需按返回的 `hasNextPage` 递增 `page`；`bangumi` 单次最多处理 6 条，建议默认 2 条分批执行。
- Bangumi 每条匹配通常只需 1 次搜索请求，条间间隔 100ms；标题完全一致记 1、包含关系记 0.9，其他按二元组重合度估算，同分时优先选择与查询标题长度更接近的候选（避免「第2期」错配到第一季）。
- 置信度 ≥ 0.86 自动写入 `bgm_id`、中文名、简介与评分，否则写入 `match_review` 并置 `match_status: 'review'`；传 `retryReview: true` 可对审核项重跑一次（`match_attempts` 达到 2 后不再重试）。
- Bangumi 条目本身没有中文名（如「しろたん」）时，`name_cn` 与日文相同，标题仍显示日文，属正常情况。
- 外部请求均设置超时（Bangumi 2.5 秒、AniList 4 秒），超时返回可读错误而不是等到云函数被平台强杀；云函数本身的超时仍建议在控制台调到 60 秒。
- `animeschedule` 需要云函数环境变量 `ANIMESCHEDULE_TOKEN`，可选 `ANIMESCHEDULE_BASE_URL`（默认 `https://api.animeschedule.net/api/v3`）；未配置 Token 时该 action 返回失败，不影响 `season` / `schedules`。
- Bangumi 域名可通过环境变量 `BANGUMI_BASE_URL` 覆盖，默认 `https://api.bgmapi.com`。
- 数组型 `data_sources`、Date 类型时间字段由服务端 SDK 写入，不受控制台 JSON 模式空值限制。
