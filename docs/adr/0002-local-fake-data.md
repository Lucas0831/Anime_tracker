# ADR-0002：原型阶段使用本地假数据，不接真实接口

- 状态：已接受
- 日期：2026-11-05
- 相关：[IMPLEMENTATION](../IMPLEMENTATION.md#1-数据模型)

## 背景

追番助手的数据涉及番剧标题、放送时间（北京时间）、集数、评分、平台与海报。真实数据来源尚未确定，抓取或第三方接口都存在稳定性、版权与合规问题；PRD 也明确正式方案为云开发 + 云数据库，不使用第三方 SDK。

原型阶段的目标是验证**信息架构与交互**，数据本身的真实度不是验收标准。

## 决策

原型不发起任何网络请求，全部数据写死在 `prototype/data.js`：

- `window.WEEK`：2026-10-26 ~ 11-01 共 7 天；
- `window.TODAY_INDEX = 0`：默认聚焦周一；
- `window.ANIME`：21 部假番剧，按天分布 9 / 2 / 2 / 2 / 2 / 2 / 2；
- `window.SEARCH_HISTORY`：搜索历史初始数据；
- 海报为本地 `assets/*.jpg`（10 张裁切自原型图，11 张本地生成），不引用外链。

筛选、搜索关键词等状态仅存于内存，刷新即重置。

## 后果

### 正面

- 离线可演示，不受接口、网络与数据源波动影响。
- 数据可精确控制，能覆盖空状态、国创、多评分、下一集倒计时等边界。
- 无隐私与版权风险，仓库可安全分发。

### 负面 / 代价

- 数据不具时效性，无法验证真实数据质量与分页、缓存等能力。
- 迁移到云开发时需要重新设计数据表结构、索引与同步策略。
- 假数据字段（如评分、平台）可能与真实来源不一致。

## 替代方案

- **接入公开动画 API**：能验证真实链路，但来源不稳定、字段不齐、存在版权与合规风险，且会让原型依赖网络。不采用。
- **本地 mock 服务（JSON Server 等）**：更接近真实请求，但需要额外进程与端口，违背"双击即开"的约束。不采用。
