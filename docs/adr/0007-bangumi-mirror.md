# ADR-0007：Bangumi 改用镜像域名并收紧请求超时

- 状态：已接受
- 日期：2026-11-06
- 相关：[ADR-0006](0006-editorial-api-sync.md) / [字段与接口来源文档](../字段接口来源文档.md)

## 背景

`animeSync` 的 `bangumi` action 持续返回 `-504003 FUNCTIONS_TIME_LIMIT_EXCEEDED`（云函数超时 5 秒），无法完成中文名匹配。

排查结论：

- 云函数部署超时确为 5 秒（CLI 查询 `timeout: 5`）；
- 无代理直连官方 `api.bgm.tv` 时，20 秒仍无法建立 TCP 连接；本机经系统代理访问同一接口 0.9 秒返回。云函数运行环境没有系统代理；
- `lib/http.js` 没有设置请求超时，连接挂起后只能等平台 5 秒强制终止，日志中看不到具体失败原因；
- 单条匹配串行发起「搜索 + 详情」2 次请求，叠加 200ms 间隔与列表查询，即使网络正常也容易吃满 5 秒；
- `timeBudgetMs` 只在循环开头判断，单条匹配内部的请求无法被预算中断。

## 决策

1. Bangumi 默认域名改为镜像 `https://api.bgmapi.com`，可用环境变量 `BANGUMI_BASE_URL` 覆盖回官方域名。
2. `lib/http.js` 增加请求级超时（默认 5 秒），连不上或响应挂起时主动失败并返回可读错误。
3. Bangumi 请求超时 2.5 秒；AniList 请求超时 4 秒。
4. 匹配成功直接使用搜索结果自带的 `name_cn` / `summary` / `rating` / `total_episodes`，不再固定请求详情；仅当候选缺少中文名时才补一次 `GET /v0/subjects/{id}`。
5. `bangumi` 默认 `limit` 2、最大 6，并在剩余预算不足 1800ms 时停止。
6. 相似度：完全一致 1、包含关系 0.9、其他按二元组重合度估算；同分时优先选择与查询标题长度更接近的候选。审核项可用 `retryReview: true` 重跑一次。

## 后果

### 正面

- 云端实测 `{"action":"bangumi","limit":2}` 在 3.8 秒内完成，2 条全部匹配，不再超时；
- 分批执行后 100 条番剧中 89 条已有中文名，剩余 11 条为 Bangumi 无对应条目或本身无中文译名；
- 单条匹配通常只发 1 次请求，链路慢时也能在预算内失败并返回原因；
- 镜像返回字段与官方 v0 一致，客户端与字段映射无需调整。

### 负面 / 代价

- 依赖第三方镜像的可用性；镜像不可用时需通过 `BANGUMI_BASE_URL` 切换域名；
- 云函数 5 秒上限仍偏紧，批量匹配需多次调用（每次 3 条），完整补齐 100 条需分批执行；
- 搜索结果缺少 `summary` 的条目不会补简介，仅写入中文名与评分。

## 替代方案

- 方案 A：维持官方域名，仅把云函数超时调到 60 秒。放弃：直连官方域名仍不可达，调超时只是延长等待。
- 方案 B：在云函数中配置 HTTP 代理。放弃：微信云开发不提供代理配置，且引入额外网络依赖。
- 方案 C：放弃 Bangumi，只保留 AniList。放弃：缺少中文名与中文简介，不符合产品目标。
