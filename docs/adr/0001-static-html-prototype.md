# ADR-0001：采用纯静态 HTML/CSS/JS 单页原型

- 状态：已接受
- 日期：2026-11-05
- 相关：[DESIGN](../DESIGN.md)、[初版PRD](../../初版PRD.md)

## 背景

目前处于需求验证阶段，需要把 PRD 与四张原型图变成可点击、可演示、可评审的产物，用于确认信息架构、页面路径与交互手感。正式产品规划为 uni-app + Vue + 云开发，但此时直接搭工程会引入编译、依赖、环境配置与小程序发布流程，反馈周期长，且大部分时间会花在工程化而非验证设计上。

约束：

- 需要在任意电脑上直接打开演示，不依赖网络与后端。
- 原型随时可能大改，维护成本要低。
- 需要移动端真实比例（390 × 844）查看效果。

## 决策

原型采用**纯静态 HTML + CSS + 原生 JS**，无框架、无构建、无第三方依赖，产出集中在 `prototype/`：

- `index.html` 只负责手机壳骨架与脚本加载；
- `styles.css` 承载全部视觉与响应式规则；
- `data.js` 存放假数据；
- `app.js` 负责路由、渲染与交互。

可直接双击 `prototype/index.html` 以 `file://` 运行，也可用 `python -m http.server` 启动本地服务。

## 后果

### 正面

- 零安装、零构建，打开即演示，评审与截图成本极低。
- 改动即时生效，适合高频调整设计。
- 无依赖，不受包版本、网络与 CI 影响。

### 负面 / 代价

- 没有组件化与类型检查，页面增多后模板字符串会变长。
- 无法直接复用为小程序代码，迁移到 uni-app 时需要重写视图层。
- 无构建意味着没有压缩、按需加载等生产优化。

## 替代方案

- **直接创建 uni-app 工程**：更接近正式实现，但需安装依赖、编译与小程序开发者工具，迭代慢，且会过早锁定组件结构。原型阶段不采用。
- **使用 Vue/React + Vite 的 Web 原型**：组件化更好，但引入 Node 环境与构建链，违背"随处可打开"的约束。原型阶段不采用。
