# ADR-0008：搜索改为首页内底部浮层

- 状态：已接受
- 日期：2026-11-06
- 相关：[PRD](../../初版PRD.md)、[DESIGN](../DESIGN.md)、[PAGE_SPEC](../PAGE_SPEC.md)、[IMPLEMENTATION](../IMPLEMENTATION.md)

## 背景

搜索最初是独立页面（原型 `#/search`，小程序 `pages/search/search`）。这种形态无法表达搜索与当前浏览页的层级关系：背景页不能随浮层一起压暗，页面切换也缺少可感知的空间连续性。需要在不引入新框架的前提下，让搜索以底部弹层出现，并能用手指上下拖拽关闭。

## 决策

搜索改为覆盖在当前浏览页上的底部浮层：

- 原型保留 `#/search` 作为浮层开关的路由，背景仍渲染来源浏览页；关闭后回到来源路由并恢复滚动位置。
- 小程序移除 `pages/search/search`，由 `src/components/SearchSheet.vue` 内嵌在 `pages/index/index` 中；搜索不再是独立路由。
- 浮层高度为视口减去顶部 56px（小程序 108rpx），打开时背景页保持原尺寸、仅整体压暗；使用约 500ms 弹簧曲线 `cubic-bezier(0.22, 1.12, 0.36, 1)`。
- 只允许从浮层顶部的指示条与搜索框区域发起拖拽，避免与正文滚动冲突；向上拖带 30% 阻力，向下拖跟手。
- 关闭判定：下拖超过面板高度 1/3，或下甩速度超过 0.8px/ms；否则弹回原位。取消按钮、遮罩点击与 Esc 也可关闭。
- 从搜索结果进入详情时收起浮层，详情返回来源浏览页。

## 后果

### 正面

- 搜索与浏览页共享同一视觉空间，背景压暗让层级关系清晰，切换更连续。
- 小程序页面路由从 3 个收敛为 2 个（`pages/index/index`、`pages/detail/detail`），返回栈更简单。
- 浮层状态与主页同处一页，可直接复用 `store.js` 的搜索状态与筛选状态。

### 负面 / 代价

- 小程序无法通过 URL 直接深链到搜索；搜索只能从首页底部胶囊进入。
- 浮层拖拽与原生页面滚动、输入聚焦存在交互竞争，需要明确拖拽热区与阈值。
- 原型需要额外维护浮层挂载 / 卸载与来源页滚动位置恢复逻辑。

## 替代方案

- 方案 A：保留独立搜索页，仅做样式调整。无法实现背景压暗与浮层覆盖的层级关系，不满足需求。
- 方案 B：小程序使用 `page-container` 等平台弹层组件。跨端不一致，且原型无法对应实现。
- 方案 C：把搜索内容直接做成首页内一个常驻区块。需要改动首页滚动结构，且失去模态语义。
